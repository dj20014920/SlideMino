# 설계의도

## 작업 개요
기존 GameOnboardingOverlay(점수 달성 시 전체 모달로 기능 안내)를 경량화된 순차 인터랙티브 온보딩 시스템으로 대체. 50점 첫 스킨 보상 수령 후 무료 스킨 뽑기를 마치면, 3개 기능을 순서대로 "스포트라이트 + 한줄요약 + 지금열기버튼 + 탭하여 넘어감" 방식으로 소개한다.

## 핵심 설계 결정

### 결정 1: 순차 온보딩 도입 (SequentialOnboardingOverlay + sequentialOnboardingService)
- **선택지**: A) 기존 GameOnboardingOverlay 유지 vs B) 새 순차 온보딩 시스템 구축
- **선택**: B
- **이유**: 기존 시스템은 각 기능을 독립된 전체화면 모달로 보여줘 사용자에게 부담. 스포트라이트를 통해 특정 UI 요소를 직접 가리키고, 한줄요약으로 가볍게 읽고 탭하여 다음 단계로 넘어가는 방식이 캐주얼 게임 UX에 더 적합.

### 결정 2: 스포트라이트 + createPortal 방식
- **선택지**: A) z-index 스택 오버레이 vs B) createPortal(document.body)
- **선택**: B
- **이유**: createPortal로 body에 직접 렌더링하여 기존 컴포넌트 트리의 z-index 계층과 독립적으로 동작. z-[9998]로 다른 모달(9999) 아래에 위치.

### 결정 3: data-tutorial-anchor 속성 기반 타겟팅
- **선택지**: A) id만 사용 vs B) data-tutorial-anchor 커스텀 속성 + id 폴백
- **선택**: B
- **이유**: 동일 컴포넌트가 프리미엄/일반 UI에서 서로 다른 id/클래스를 가질 수 있으므로, data 속성으로 통일된 셀렉터 제공. id는 폴백으로 유지.

### 결정 4: 타겟 미발견 시 자동 진행 (1.5초)
- **선택지**: A) 무한 대기 vs B) 일정 시간 후 자동 진행
- **선택**: B (1.5초)
- **이유**: 특정 조건에서만 렌더링되는 요소(예: #continue-btn은 저장된 게임 있을 때만)를 대상으로 하는 단계에서 사용자가 영원히 진행할 수 없는 상태 방지.

### 결정 5: localStorage 기반 진행 상태 관리
- **선택지**: A) 서버 저장 vs B) localStorage
- **선택**: B
- **이유**: 온보딩 상태는 클라이언트 전용 데이터. 서버 왕복 불필요. 기존 점수 기반 온보딩과 일관된 방식.

### 결정 6: 온보딩 시작 시점 — 무료 스킨 뽑기 완료 후 SkinModal onClose
- **선택지**: A) SkinModal onClose에서 직접 시작 vs B) useEffect로 showFirstSkinRewardModal 전이 감지
- **선택**: A (현재 구현 유지)
- **이유**: 무료 뽑기 후 SkinModal이 닫힐 때가 온보딩을 시작하기에 자연스러운 시점. 사용자가 스킨을 착용/확인할 시간을 가진 후 안내 시작.

### 결정 7: GameOnboardingOverlay 삭제 및 onboardingService 경량화
- **선택지**: A) 기존 유지하며 병행 vs B) 완전 교체
- **선택**: B
- **이유**: 두 온보딩 시스템이 동시에 트리거되는 혼란 방지. 점수 기반 온보딩(skin)만 유지하고 나머지 제거.

### 결정 8: 6단계 → 3단계 축소 (Option B)
- **단계 구성**: 1) leaderboard (랭킹+주간이벤트) 2) daily_activities (미션+출석+레벨) 3) game_resume (이어하기)
- **선택**: Option B (3단계) — "경쟁 / 일일활동 / 플레이" 그룹핑
- **이유**: 6단계는 캐주얼 게임에 인지 부하가 높음. "미션+출석+레벨"을 하나로 묶어 자연스러운 성장 스토리 제공. 랭킹과 주간이벤트는 점수 경쟁이라는 공통 관심사로 그룹핑.

### 결정 9: 각 단계에 "지금 열기" CTA 버튼 추가
- **선택**: 추가
- **이유**: 사용자가 설명을 읽고 즉시 해당 기능으로 이동할 수 있도록 함. 버튼 탭 시 온보딩이 먼저 advance된 후 기능 모달이 열려 z-index 충돌 방지.
- **메커니즘**: CTA 탭 → setIsSeqOnboardingVisible(false) + advanceSequentialStep() → pendingSeqStep 저장 → 모달 열기 → 모달 닫힘 → pendingSeqStep 확인 후 재개

### 결정 10: 각 단계에 "터치 시 다음으로" UX 힌트 표시
- **선택**: 추가
- **이유**: 사용자가 온보딩 진행 방식을 직관적으로 이해할 수 있도록 카드 하단에 작은 힌트 텍스트 표시.

## 의도적으로 제외한 것
- **건너뛰기/닫기 버튼**: 의도적으로 제외. 각 단계가 가볍고 빠르게 진행되므로 건너뛸 필요성 낮음. 필요시 배경 탭으로 항상 진행 가능.
- **접근성(aria/키보드)**: 현재 버전에서 지연. 순수 터치 기반 캐주얼 게임 특성상 우선순위 낮음.
- **서버 저장/동기화**: 온보딩 상태는 클라이언트 전용으로 충분.

## 주의사항
- **z-index 충돌**: overlay는 9998, firstSkinRewardModal은 9999. 다른 모달이 열릴 때 overlay가 함께 보일 수 있음.
- **타겟 요소 가용성**: #mission-nav-btn, #leaderboard-btn 등이 모든 UI 상태에서 존재하는지 확인 필요.
- **프리미엄/일반 이중 렌더링**: 두 UI 테마에서 모두 data-tutorial-anchor가 올바르게 설정되어야 함.
- **로케일 누락**: 모든 텍스트 키가 KO/EN/JA/ZH 모두 존재해야 함.
- **자동 진행 조건**: spotlight=null일 때만 auto-advance. 타겟이 존재하지만 사용자가 못 찾는 경우는 대응 불가.
- **"지금 열기" 버튼 동작**: 온보딩 advance 후 기능 모달이 열리므로, 모달이 열린 상태에서 overlay는 보이지 않음.
